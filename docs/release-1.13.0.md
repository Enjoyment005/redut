# Редут 1.13.0 — DNS Rescue как изолированный последний режим

Дата: 2026-09-06

## Главное

DNS Rescue встроен в Редут как отдельный аварийный режим после исчерпания обычной
лестницы восстановления. Обновление само его не включает: миграция ставит
`mode=disabled`, `owner_approved=false`, `automatic_ready=false`.

Режим запускает второй, изолированный процесс sing-box 1.11.7 на высоком порту
адреса WireGuard. Только IPv4 DNS клиентов (`UDP/TCP 53`, входящий через `wg0`)
перенаправляется в собственную цепочку `REDUT_DNS_RESCUE`. Основной конфиг
sing-box, IPv6, DoH/DoT внутри приложений и DNS старых клиентов вне WireGuard не
перехватываются и не объявляются защищёнными.

## Предохранители

- четыре режима: `disabled`, `observe_only`, `manual_canary`,
  `automatic_last_resort`;
- отдельные SQLite-таблицы состояния, операции и проб; QNAME, пакеты, endpoint и
  произвольные ошибки в журнал не попадают;
- не более четырёх заранее проверенных слотов, для автоматики — минимум два
  независимых оператора; proxy-кандидаты идут первыми;
- единая блокировка с ротацией прокси и повторное чтение состояния после lock;
- одна автоматическая попытка на долговечный инцидент, deadline 30 секунд;
- UDP и TCP должны пройти до и после установки redirect;
- 50 запросов/с на peer, три подряд ошибки активного шлюза и TTL 15 минут ведут
  к fail-open: сначала снимается redirect, затем останавливается процесс;
- возврат к обычному DNS — после трёх успешных проверок с интервалом 60 секунд;
- автоматический режим не активируется при ручной аварии, паузе автоматики,
  невалидном конфиге или без двух явных флагов владельца.

## Надёжность узла

- подтверждённый прямой аварийный выход получил durable intent в
  `/var/lib/vpn-panel/emergency.intent` и переживает reboot;
- `watchdog` и `ExecStartPost` больше не являются параллельными писателями
  таблицы `middleman` — изменения координирует vpn-agent;
- boot-скрипт очищает только собственную цепочку `REDUT_PREROUTING`, но не
  встроенный `mangle/PREROUTING`;
- sing-box скачивается по закреплённой версии и SHA256, проверяется до атомарной
  замены; основной конфиг тоже сначала проходит `sing-box check` как candidate;
- RU allowlist читает ровно три файла закреплённого коммита с SHA256, проверяет
  глобальность/масштаб сетей, использует candidate + LKG и больше не запускает
  boot-скрипт после обновления.

## Управление

```bash
vpn-agent dns-rescue status
vpn-agent dns-rescue observe
vpn-agent dns-rescue activate --scope peer:10.8.0.5 --slot cloudflare-proxy
vpn-agent dns-rescue activate --scope all
vpn-agent dns-rescue deactivate
vpn-agent dns-rescue reconcile
```

Статус и действия также доступны в аутентифицированном API
`GET/POST /api/dns-rescue`; главная панель показывает фазу и ограниченный охват.

## Проверка релиза

- чистые unit/integration tests канонической и публичной сборок;
- отдельные тесты схемы, typed saga, privacy-журнала, slot/owner/auto gates,
  UDP/TCP wire parser, owned firewall chain, peer scope, rollback и one-shot;
- реальный sing-box 1.11.7 проверен командой `check`, затем отдельным процессом:
  UDP и TCP запросы через high-port listener получили валидные ответы через DoH;
- live Linux canary с реальным `iptables`/WireGuard в этот релиз не входил,
  поэтому автоматическая активация после обновления остаётся закрытой.
