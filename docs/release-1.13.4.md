# Редут 1.13.4 — DNS Rescue и провайдеры прокси

Дата: 8 сентября 2026 года.

Выпуск добавляет в панель каталог, покупку и продление ProxyWing, исправляет
работу PROXY6 и ProxyLine и повышает устойчивость DNS Rescue.

## ProxyWing

- Раздельные каталоги **Datacenter / ISP**, наличие, цена и фильтр типа в пуле.
- Покупка месячного пакета и продление **всего заказа** на 1/3/6/12 месяцев
  по актуальным ценам API.
- Отдельный бюджет **USD**, который владелец должен явно задать перед покупкой.
  Общий запрет денежных операций продолжает действовать.
- Журнал операций и постоянный Idempotency-Key защищают повтор после потери ответа.
  Неопределённый результат не считается оплатой; повтор проверяет исходную цену и лимиты.
- Новые оплаченные каналы импортируются с ролью `off`, в том числе после сбоя импорта.

Подробности: [настройка ProxyWing и ограничения](proxywing-integration.md).

## PROXY6 и ProxyLine

- Неполный или противоречивый ответ списка прокси сохраняет прежний пул.
- PROXY6 проверяет валюту ответа и считает цену продления по фактическому типу прокси.
- Некорректный срок отклоняется до отправки операции провайдеру.
- В панели появился каталог ProxyLine: индивидуальные и общие прокси, наличие
  и расчёт цены нового заказа. Типы ответа API сопоставляются с выбранным продуктом.
- **Покупка и продление ProxyLine остаются через кабинет провайдера.** Защита денежных
  операций не снята: подтверждённого контракта безопасной оплаты и цены продления пока нет.

Подробности: [результаты проверки PROXY6 и ProxyLine](other-providers-audit.md).

## DNS Rescue

- Контракт внешнего runner v4 требует три раунда доказательств DNS-причины,
  включая ложный UDP NXDOMAIN при рабочем TCP. Проверяются реально присутствующие
  классы профилей; состав WireGuard-пиров и маршрут должны оставаться неизменными.
- Результат `UNKNOWN` сохраняет работающий DNS, не увеличивает счётчик отказов
  и блокирует новое переключение. После 15 минут панель показывает предупреждение.
- Возврат требует выдержки минимум 300 секунд и трёх успешных проверок через 60 секунд.
- После снятия перенаправления штатный DNS доказывается новым запросом при ещё работающем
  listener. При ошибке или неопределённом результате прежний Rescue восстанавливается.
- Аварийное снятие перенаправления при неработающем listener и истечении isolated TTL
  сохраняется; старые глобальные правила очищаются с отдельной записью в журнале.

Подробности: [контракт runner v4](dns-canary-runner-contract.md).

## Проверки и условия применения

- Полные локальные canonical/public наборы: по **1281 тесту, OK (skipped=3)**.
- Независимые финальные аудиты пройдены, подтверждённые дефекты исправлены.
- Проверены JavaScript панели, install/reinstall и миграции, Python, shell и JSON,
  отсутствие секретов, пробелы в diff и соответствие canonical/public.
- Выполнены живые чтения API PROXY6/ProxyLine и расчёт цены без списаний.
- **Выпуск без серверной приёмки (`--untested`).** Реальные покупки и продления
  в ходе проверки не выполнялись. Deploy dry-run ограничен отсутствием записи `node2`
  в локальном реестре серверов.
- **Автоматический DNS Rescue остаётся выключенным.** Физические проверки отключения
  сети, перезагрузки, Android-кэша и нагрузки ещё не проведены. Включение автоматики
  требует этих доказательств и отдельного разрешения владельца.

Публикация проходит через штатные проверки release.py, включая Linux CI кандидата,
main и тега, затем сверку GitHub Release, версии обновления и архива тега.
