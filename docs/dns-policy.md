# DNS каждого контура

Во вкладках «Основной» и «2 контур» есть раздел «DNS контура». Настройка принадлежит выбранному контуру, сохраняется при ручной и автоматической смене выхода и не переносит устройства между контурами. При выборе режима сразу показывается его краткое описание и ограничения, даже если общие объяснения в панели выключены. Действующий режим указан отдельно; выбор в списке не меняет DNS до нажатия «Применить DNS».

- **DNS провайдера — на стороне прокси.** РЕДУТ передаёт имя сайта выбранному SOCKS, HTTP или VLESS-серверу. Адрес определяет сервер выхода своим DNS. Этот режим подходит для использования DNS провайдера, включая ZenXNet.
- **Провайдер — строгий.** Только во втором контуре: все имена сайтов передаются выбранному ZenXNet, без российских исключений, отдельного публичного DNS и аварийного прямого выхода. Если выбранный прокси недоступен, этот путь закрывается.
- **Cloudflare — через прокси.** Обычные DNS-ответы через DoH `1.1.1.1`, транспорт — выход этого контура. Страна Cloudflare может отличаться от страны прокси.
- **DNS сервера (старый режим).** Так отображается основной контур старой установки, пока пользователь явно не применил новую настройку. Обновление кода само по себе не меняет работающий DNS.

DNS контролируется для IPv4 UDP/TCP порта 53 устройств WireGuard. Защищённый DNS браузера, Private DNS Android и DNS внутри другого приложения могут обходить эту настройку. Отключите собственный DNS приложения, если нужен DNS контура. Во втором контуре блокируется IPv6, который попал на сервер через WireGuard. IPv6 устройства, идущий вне туннеля, сервер не контролирует: его нужно отключить на самом устройстве или закрыть клиентскими правилами VPN.

В обоих режимах DNS провайдера имена сайтов сначала получают внутренние адреса FakeIP с TTL 60 секунд. При соединении ядро восстанавливает имя и передаёт его прокси. Для каждого контура выделены отдельный диапазон и постоянный кэш: `198.19.0.0/17` и `198.19.128.0/17`. Кэш сохраняется после перезапуска, смены сервера и возврата к Cloudflare. Эти адреса не являются внешними IP. После переноса устройства между контурами его старые DNS-ответы могут действовать до истечения TTL; при необходимости переподключите приложение и очистите его DNS-кэш.

В обычном режиме «DNS провайдера» домены `.ru`, `.su`, `.рф`, доменные исключения `ru-whitelist.conf` и проверочные домены DNS Rescue получают обычные ответы через Cloudflare внутри этого контура. Служебные типы DNS (например TXT, MX, SRV) также используют этот путь. AAAA, HTTPS и SVCB в режиме провайдера получают пустой ответ, чтобы адресные подсказки не обходили передачу имени. Автоматическое исключение по российскому IP для других доменных имён в этом режиме не действует: IP определяет удалённый прокси. Прямые соединения к явно указанным российским IP сохраняют прежние правила. Для полного сохранения исключений по IP используйте Cloudflare. Изменение доменного списка учитывается при повторном применении DNS или смене выхода; новые исключения до этого не получают FakeIP в общем ipset.

Первый контур после явного применения использует отдельный клиентский dnsmasq на порту 5352 и локальный вход ядра 5353. DNS самого сервера на порту 53 остаётся отдельным. Второй контур использует свой dnsmasq 5354 и ядро 5355. Перехват ограничен устройствами соответствующего контура, собственный DNS второго контура не попадает в первый. До запуска WireGuard загрузочная защита закрывает обход клиентского DNS. В обычных режимах при аварийном прямом выходе действуют прежние правила; изменение DNS до его отключения недоступно. Строгий режим запрещает аварийный прямой выход.

## Строгий режим второго контура

Строгий режим меняет правила всего второго контура. Российские домены и IP идут через тот же выбранный прокси, что и остальные внешние адреса. РЕДУТ не добавляет российский DNS и не переключается незаметно на DNS сервера, Cloudflare, AliDNS или прямой интернет при отказе. Основной контур сохраняет свои настройки. При ручном выборе отказ сервера не снимает фиксацию и не включает автоматический выбор: интерфейс показывает сбой. Если пользователь явно выбрал AUTO, разрешена обычная смена серверов провайдера, но прямой аварийный выход остаётся запрещён.

A-запросы получают FakeIP, а имя определяется на стороне ZenXNet при соединении. Для AAAA, HTTPS и SVCB возвращается пустой ответ. Остальные типы, включая TXT, MX и SRV, получают `REFUSED`: передать такой запрос через обычное прокси-соединение невозможно без отдельного DNS-сервера. Приложениям, которым нужны эти записи, строгий режим может не подойти. Это намеренный отказ вместо скрытой подмены резолвера.

У подключённого к WireGuard устройства второго контура появляется HTTP/SOCKS5-прокси. Его адрес показан в разделе «DNS контура» (обычно `10.10.10.1:10802`). В Chrome на Windows укажите этот адрес в настройках прокси браузера или Windows, чтобы имена сайтов определялись удалённо, как при прямом подключении к ZenXNet. В SOCKS-клиенте должен быть включён удалённый DNS. С первого контура и из интернета этот вход недоступен.

Отключите Secure DNS браузера и собственный DNS приложения для проверки DNS контура. Один WireGuard не позволяет серверу подменить произвольный зашифрованный DoH внутри HTTPS. Адреса, которые клиент разрешил сам, и DNS из старого кэша также не становятся автоматически именами для прокси. После переключения очистите DNS-кэш и перезапустите проверяемое приложение.

Строгий режим не исполняет целиком профиль Happ и не гарантирует страну рекурсора ZenXNet. В проверенной подписке Happ указаны Cloudflare `1.1.1.1` и `1.0.0.1`; это отдельная настройка клиента. При передаче имени через прокси резолвер выбирает сам ZenXNet. Его нельзя обещать китайским для каждого домена или заменить на AliDNS под названием «DNS провайдера». Сравнивать нужно одно и то же приложение, выбранный сервер и способ подключения.

Применение выполняется под общей блокировкой сетевых изменений: проверка ядром → точный бэкап → журнал операции → атомарная замена → перезапуск только выбранного контура → проверка DNS UDP/TCP и реального HTTPS через полученный адрес. При сбое восстанавливается предыдущая конфигурация. Незавершённая операция восстанавливается штатным recovery; неизвестная более новая конфигурация не затирается. DNS Rescue и незавершённые операции блокируют конфликтующее изменение. Установка и повторная установка доставляют один и тот же модуль через штатный сборщик публичной копии.

CLI:

```sh
vpn-agent --contour 2 dns-policy status
vpn-agent --contour 2 dns-policy set --mode provider_strict --dry-run
vpn-agent --contour 2 dns-policy set --mode provider_strict
vpn-agent --contour 2 dns-policy set --mode provider
vpn-agent --contour 2 dns-policy set --mode cloudflare
```

Смена DNS не меняет провайдера, ручную фиксацию, денежную автоматику и назначения устройств. Она не заставляет провайдера использовать одну страну или один выходной IP для всех сайтов. Приёмка ZenXNet на Vadim выполняется отдельно от публикации GitHub.
