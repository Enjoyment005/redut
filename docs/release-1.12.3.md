# Редут 1.12.3 — маяк обновлений спрашивается через API, а не из кэша CDN

Дата подготовки: 2026-08-22.

## Главное

1.12.2 обещал, что панель увидит свежий выпуск сразу. Обещание не сработало: обход кэша был
сделан меняющимся параметром `?ts=<epoch>` в адресе `raw.githubusercontent.com`, а Fastly не
берёт query-строку в ключ кэша. Проверка 22.08: ответ на такой адрес приходит с `X-Cache: HIT`
и старым содержимым, то есть узел по-прежнему пять минут видел бы предыдущую версию.

Настоящее решение — сменить источник. Contents API отдаёт тот же файл с `Cache-Control:
max-age=60` и показывает новую версию сразу после публикации.

## Что изменилось

- `update.beacon_sources()` описывает источники по приоритету: Contents API
  (`https://api.github.com/repos/<repo>/contents/VERSION?ref=main`, заголовок
  `Accept: application/vnd.github.raw`), затем прежний raw-адрес.
- `update.fetch_beacon()` берёт первый источник, который ответил внятной версией `X.Y.Z`.
  Мусор вместо версии (например, JSON, если Accept не дошёл) считается отказом источника,
  а не ошибкой проверки — раньше это уронило бы проверку целиком.
- raw остаётся запасным: он может отставать до пяти минут, но это лучше, чем «маяк недоступен»,
  если API исчерпал лимит (60 запросов в час на адрес без ключа) или закрыт у хостера.
- `fetch_text()` принимает дополнительные заголовки и всегда шлёт `Cache-Control: no-cache` и
  `Pragma: no-cache` — придержать ответ способен и прокси провайдера.
- Оба источника мертвы — ошибка одна, с перечислением причин; флаг `network` остаётся честным:
  он ставится, только если все отказы были сетевые.

## Совместимость

Формат `VERSION`, разбор версий, чёрный список неудачных версий, окно автообновления и путь
установки не тронуты. Изменился только способ спросить версию.

## Проверка

- Канонический набор: 789 тестов — OK.
- Публичный набор: 789 тестов — OK.
- Новое покрытие: API спрашивается первым и с нужным Accept; при отказе API берётся raw;
  JSON вместо версии не роняет проверку; смерть обоих источников — одна сетевая ошибка.
- Живая проверка на GitHub: сразу после публикации 1.12.2 raw отдавал `1.12.1`
  (`X-Cache: HIT`), Contents API — `1.12.2`.
