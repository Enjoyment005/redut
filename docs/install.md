# Установка и первые шаги

## Что понадобится

| | |
|---|---|
| Сервер | VPS у российского хостера: 1 vCPU, 1 ГБ RAM, 10 ГБ диска, **чистая Debian 13**, root-доступ по SSH |
| Устройства | бесплатное приложение WireGuard (App Store, Google Play, Windows, macOS, Linux) |
| Аккаунт прокси-сервиса | нужен для динамических каналов — см. ниже. Без него туннель тоже работает, но исходящего канала у узла нет: устройства выходят в интернет напрямую через адрес сервера (панель показывает это как «аварийный режим») |
| Ваш компьютер | ничего, если ставите одной командой на сервере; Python 3.9+ и `paramiko` — если через оркестратор |

### Аккаунт для исходящих каналов

Узел берёт адреса по API, поэтому нужен аккаунт у сервиса аренды прокси. Рекомендуем те, с
которыми работаем:

| Сервис | Ссылка | Промокод | Скидка |
|---|---|---|---|
| **PROXY6** (основной: рубли, покупка и продление прямо из панели) | [proxy6.net](https://proxy6.net) | `red12` | 5% пожизненно |
| **ProxyLine** (как второй источник) | [proxyline.net](https://proxyline.net) | `red12` | 10% |
| **ProxyWing** (datacenter/ISP; уже купленные каналы) | [proxywing.com](https://proxywing.com) | — | — |

Зарегистрируйтесь, пополните баланс с промокодом `red12`, скопируйте API-ключ из кабинета —
он понадобится на третьем шаге мастера: без хотя бы одного рабочего ключа мастер не
завершить. Сам туннель поднимается и до этого (устройства выходят напрямую через сервер),
но динамических каналов без ключа не будет.

Почему именно российский хостер — [отдельный документ](why-russian-server.md).

## Шаг 1. Одна команда на сервере

Зайдите на сервер по SSH под root и вставьте:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Enjoyment005/redut/main/setup.sh || wget -qO- https://raw.githubusercontent.com/Enjoyment005/redut/main/setup.sh)
```

Команда берёт `curl`, а если его нет — `wget`: на минимальных образах Debian 13 у хостеров
(netinst) `curl` обычно не установлен, а `wget` есть. Если нет ни того, ни другого —
`apt-get install -y curl` и повторите.

Параметры задаются переменными окружения перед командой:

```bash
NAME=home PANEL_PORT=9443 SUBNET=10.9.0.0/24 CLIENTS=phone,laptop \
  bash <(curl -fsSL https://raw.githubusercontent.com/Enjoyment005/redut/main/setup.sh || wget -qO- https://raw.githubusercontent.com/Enjoyment005/redut/main/setup.sh)
```

* `CLIENTS` принимает список имён (`phone,laptop`), число (`3` → `client1..client3`) или
  пару `имя:адрес` (`phone:10.8.0.5`) — последнее нужно при переустановке поверх живого узла,
  чтобы у клиента не поменялся IP;
* `SRC_DIR=/path/to/repo` — поставить из уже скачанного репозитория, ничего не качая.

> Почему `bash <(curl …)`, а не `curl … | bash`: при пайпе у скрипта нет доступа к терминалу,
> и он не может ничего спросить или показать интерактивно. Такая форма — корректнее.

## Альтернатива: установка с рабочей машины

Если серверов несколько, удобнее оркестратор по SSH — тогда на вашем компьютере нужен
Python 3.9+ и `pip install paramiko`:

```bash
python install/bootstrap.py --host ВАШ_IP --pw ROOT_ПАРОЛЬ --name node1
```

Оба пути делают одно и то же, примерно за 4 минуты:

1. определит сетевые параметры сервера (шлюз, интерфейс, внешний адрес);
2. поставит пакеты, WireGuard и sing-box фиксированной версии;
3. сгенерирует ключи сервера и первого клиента;
4. настроит маршрутизацию и правила, которые переживают перезагрузку;
5. развернёт панель управления с самоподписанным сертификатом;
6. заберёт готовый клиентский профиль к вам в `install/clients/<имя>/`;
7. напечатает отчёт проверки.

Полезные ключи:

```bash
--clients 3                 # сразу три профиля: client1..client3
--clients phone,laptop      # или с понятными именами
--subnet 10.9.0.0/24        # своя клиентская подсеть
--panel-port 9443           # другой порт панели
--no-panel                  # только туннель, без веб-интерфейса
--dry-run                   # показать план и ничего не менять
```

## Повторный запуск: штатный способ обновиться

Ту же команду можно выполнять сколько угодно. Проверено на живом узле, что переустановка:

* **сохраняет устройства, заведённые через панель** — они не выпадают из конфигурации туннеля;
* **не сбрасывает исходящий канал**, выбранный вами или автоматикой (перебить его можно
  только явно — ключом `--upstream` у оркестратора);
* сохраняет учётную запись панели, ключи, лимиты и настройки из конфига;
* сохраняет пароль SOCKS5-прокси для приложений (`/etc/microsocks.env`);
* не задваивает правила файрвола, маршруты и задания планировщика.

## Шаг 2. Мастер первого входа

Откройте `https://ВАШ_IP:8443/setup`.

Браузер предупредит о самоподписанном сертификате — это ожидаемо. Сверьте отпечаток с тем,
что напечатал установщик, и продолжайте.

> ⚠️ **Первый вход не защищён паролем.** Панель занимает тот, кто открыл её первым, поэтому
> пройдите мастер сразу после установки.

Мастер займёт пару минут:

1. **Пароль** — лучше нажать «Сгенерировать» и сохранить результат в менеджер паролей.
2. **Двухфакторка** — отсканируйте QR приложением-аутентификатором (Google Authenticator,
   Aegis, 1Password) и сохраните резервные коды отдельно от телефона.
3. **Ключ прокси-сервиса** — вставьте API-ключ из кабинета (ссылки и промокоды выше). Панель
   проверит его сразу и покажет ваш баланс. Именно с этого момента работают динамические
   каналы: узел сам покупает, проверяет, продлевает и переключает адреса. Нужен хотя бы один
   рабочий ключ — без него мастер не завершится. До его ввода исходящего канала у узла нет:
   устройства выходят напрямую через адрес сервера, и панель показывает «аварийный режим»
   (для нового узла это норма, а не поломка). Если какой-то сервис недоступен с сервера
   напрямую (мастер напишет «сервис недоступен с сервера напрямую»), его ключ сохранится без
   проверки рядом с рабочим — узел проверит его через собственный канал сам.
   После «Завершить» узел сразу подтягивает пул и подбирает первый канал (обычно в пределах
   минуты) — панель после входа покажет адрес выхода и страну, а на карте выхода — паспорт
   адреса: оператор, сеть (ASN), датацентр ли это, часовой пояс. Смена или добавление ключа
   позже работает так же: панель заново спросит список адресов и сама проверит новые каналы.
4. **Почта для оповещений** — куда писать, если с узлом что-то случится. Тоже можно
   пропустить, но лучше настроить: иначе о проблемах вы узнаете, только заглянув в панель.
5. **Завершение** — панель закрывается паролем и вторым фактором.

## Шаг 3. Подключить устройства

В разделе «Кто подключён»:

1. впишите имя устройства латиницей — `phone-mine`, `laptop-work`;
2. нажмите «Выдать доступ»;
3. для телефона — «QR» и сканирование в приложении WireGuard;
   для компьютера — «Скачать» и импорт файла.

В списке будет видно, кто на связи и сколько трафика прошло. Кнопка «Отозвать» мгновенно
лишает устройство доступа.

## Проверка, что всё работает

На устройстве с включённым туннелем откройте любой сервис «мой IP» — он должен показать
адрес исходящего канала (или адрес вашего сервера, пока канал не выбран), но никак не адрес
вашего домашнего провайдера.

В панели нажмите «Проверить выход»: она спросит у внешнего сервиса, каким адресом виден
сервер, и покажет результат.

### Автоматический и ручной выбор канала

Новая установка начинает со стратегии **«Скорость и отклик»**. В карточке стратегий можно
переключиться на «Репутацию страны» или «Баланс» — панель сразу перепроверит лучшего кандидата
и безопасно применит его, если преимущество достаточно велико.

Кнопка **«В бой»** у конкретного прокси означает ручную фиксацию, а не одноразовую смену:
стратегии отключаются, Redut следит и продлевает выбранный канал. Единичный сбой, потеря сети
самого сервера или отдельная недоступность Telegram фиксацию не снимают. После подтверждённой
смерти прокси автоматика возвращается к «Скорость и отклик» и выбирает замену. Явный клик по
любой стратегии также снимает ручной режим.

## Что слушает сервер

| Порт | Что это | Кому доступно |
|---|---|---|
| `51820/udp` | WireGuard — сам туннель | устройствам с выданным профилем |
| `8443/tcp` | веб-панель (HTTPS) | по паролю + второму фактору; до мастера — первому вошедшему |
| `1080/tcp` | SOCKS5-прокси для приложений (по желанию: браузер или программа, которой не нужен туннель целиком) | по логину `proxyuser` и паролю, **сгенерированному при установке** — он лежит в `/etc/microsocks.env` (только root) |

Пароль SOCKS5 у каждого узла свой: установщик генерирует его случайно и печатает, где его
взять. Заглушка из репозитория в рабочий конфиг попасть не может — установщик проверяет это
рукопожатием и сообщит об ошибке. Если прокси не нужен: `systemctl disable --now microsocks`.

## Если что-то пошло не так

* **Панель не открывается.** Проверьте, что вы указали `https://` и порт `8443`, и что
  хостер не режет порт файрволом.
* **Устройство подключилось, но интернета нет.** В панели нажмите «Проверить выход», затем
  «Ротация» — узел попробует починиться сам. Загляните и в баланс прокси-сервиса на дашборде:
  без денег на счёте узлу нечем строить исходящий канал.
* **Мастер пишет, что PROXY6 недоступен с сервера.** У некоторых российских хостеров сайт
  сервиса заблокирован для прямого доступа. Введите рядом рабочий ключ второго сервиса
  (ProxyLine) — мастер сохранит ключ PROXY6 без проверки, а узел будет ходить к нему через свой
  канал, как только тот появится. Ключи можно поправить и позже в `/etc/vpn-panel/secrets.json`
  (панель перечитывает файл без перезапуска).
* **Забыт пароль панели.** Заведите учётку заново на сервере:
  `python3 /opt/vpn-panel/webpanel/setup_admin.py --label node1 --force` — скрипт напечатает
  новые данные и сам перезапустит панель, чтобы старый пароль сразу перестал действовать
  (если перезапустить не смог — напомнит: `systemctl restart vpn-panel`).
* **Сервер перезагрузили.** Ничего делать не нужно: туннель и правила поднимаются сами.
  Если исходящий канал ещё не выбран, устройства сразу после загрузки выходят напрямую через
  адрес сервера — без паузы до первой проверки сторожа.

## Обновление

Со сборки 1.2.0 узел обновляется **сам**: раз в сутки сверяет свою версию с этим репозиторием
и, когда выходит новая, ночью (окно 04:00–06:00 по времени сервера) скачивает её и
переустанавливается собственным установщиком. Доступы устройств, пароль панели, ключи и
рабочий канал не трогаются. Если после обновления что-то главное не поднялось (панель,
туннель) — узел **сам откатывается** на прежнюю версию и присылает письмо.

Управление — в панели, карточка **«Обновления»**:

* текущая версия узла и последний выпуск в репозитории;
* **«Проверить сейчас»** — спросить GitHub, не выходило ли новое;
* **«Обновить сейчас»** — не ждать ночного окна;
* выключатель **автообновления** — если хотите обновляться только вручную.

То же с сервера: `vpn-agent self-update` (проверка) и `vpn-agent self-update --apply`
(обновление сейчас).

Обновить **руками** (или обновить узел, поставленный до 1.2.0, — такие узлы за выпусками
ещё не следят) можно той же командой установки в режиме обновления:

```bash
UPDATE=1 bash <(curl -fsSL https://raw.githubusercontent.com/Enjoyment005/redut/main/setup.sh || wget -qO- https://raw.githubusercontent.com/Enjoyment005/redut/main/setup.sh)
```

`UPDATE=1` берёт имя узла, подсеть и порты с самого узла — переменные первой установки
вспоминать не нужно, лишние клиенты не добавляются. Со сборки 1.2.0 режим включается и
сам: если узел уже установлен, а `NAME`/`SUBNET`/`CLIENTS` не заданы, установщик не станет
применять значения по умолчанию к живому узлу. Повторный запуск с переменными, в точности
повторяющими первую установку, тоже работает как раньше.
